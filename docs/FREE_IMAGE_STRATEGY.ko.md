# 묵동홍어마을 무료 이미지 운영 제안

검토일: 2026-09-27. 질문형 글 방향은 유지합니다. 이 문서는 조사와 다음 구현 제안이며, 새 이미지 생성기 설치나 API 연결을 완료했다는 의미가 아닙니다.

## 추천

직접 촬영한 음식 사진과 설명용 그래픽을 고정 편집 틀에 조합하는 방식을 기본으로 삼습니다. 무료 생성 AI는 필요한 설명용 그림을 준비하는 보조 수단으로 사용합니다.

우리 콘텐츠의 첫 장은 사람들이 평소 먹는 음식의 궁금증을 보여주고, 뒤에서 홍어와 매장으로 연결합니다. 그러므로 매번 새로운 홍어 사진을 만들 필요는 없습니다. 수육, 김치, 회, 젓가락으로 고르는 한 점 등 질문에 맞는 장면을 확보하고 크게 잘라 쓰는 편이 목적에 맞습니다. 이는 편집 방향에 대한 제안이며 성과가 검증된 결과는 아닙니다.

이미지를 자동으로 자르고 글자를 얹는 작업은 외부 생성 API 없이 처리할 수 있습니다. 기존 PC에서 운영할 때 별도의 이미지 생성 API 비용은 0원이며, 촬영·편집 시간과 PC 전기·기존 서버 운영비는 별도입니다. 글 생성 비용까지 무료가 된다는 의미는 아닙니다.

## 게시물 하나의 구성 예시

주제: **수육에는 왜 김치를 곁들일까?**

1. 표지: 수육과 김치가 함께 보이는 사진에 질문을 두 줄 이내로 배치합니다. 매장명은 작게 둡니다.
2. 설명: 두 재료를 확대해 나란히 놓고, 본문에서 확인한 맛·식감의 차이를 짧게 표시합니다. 확인되지 않은 성분 작용이나 건강 효능은 넣지 않습니다.
3. 홍어 연결: 홍어·수육·묵은지를 구분해서 보여주며 글에서 설명한 조합으로 이어갑니다. 향이 사라진다고 표현하지 않습니다.
4. 매장 안내: 직접 촬영한 실제 음식 또는 매장 사진에 묵동홍어마을 이름과 메뉴 확인 안내를 배치합니다.

첫 장은 질문을 알아보게 하고, 중간 장은 차이를 이해하게 하고, 마지막 장은 실제 방문할 곳을 보여주는 역할을 맡습니다. 사진이 부족한 설명 장은 글자·선·도형으로 구성할 수 있습니다.

## AI로 만든 티를 줄이는 편집 기준

- 한 장에는 질문이나 설명 한 가지를 담습니다. 제목과 설명을 사진 위에 빽빽하게 올리지 않습니다.
- 음식이 크게 보이는 사진형, 두 재료를 비교하는 형, 글자와 간단한 도형으로 설명하는 형의 세 틀을 준비합니다.
- 한글은 이미지 생성 모델에 그리게 하지 않고 편집 단계에서 실제 글꼴로 합성합니다.
- 밝은 바탕, 짙은 글씨, 한 가지 강조색을 기본으로 하고 반짝임·과한 그림자·장식 스티커를 줄입니다.
- 같은 원본은 전체 장면, 재료 확대, 비교 배치처럼 내용에 맞게 편집합니다. 최근 사용 사진을 기록해 반복 노출을 줄입니다.
- 밝기와 색을 조절해도 실제 재료·제공량·상차림을 바꾸어 표현하지 않습니다. 자료 사진과 생성 그림은 실제 매장 사진으로 소개하지 않습니다.

## 먼저 준비할 자료

실제로 제공하는 메뉴를 기준으로 스마트폰 사진 10~15장을 모으는 것을 초기 목표로 제안합니다. 전체 상차림, 홍어 한 접시, 한 점의 단면, 실제 곁들임, 한입을 만드는 장면, 매장 입구를 서로 다른 거리에서 촬영합니다. 낮의 창가 빛과 정돈된 배경을 우선하고, 원본을 보관합니다.

기존 `Project/photos` 파일 목록을 확인했으며 `hero-family.jpg`와 `step-1.jpg`를 직접 열어 보았습니다. 두 파일은 일러스트이며 실제 매장 촬영 사진으로 분류하면 안 됩니다. 다른 파일들의 촬영 여부·사용 권한까지 확인한 것은 아닙니다.

## 다음 구현안

사진마다 음식 종류, 사용 가능한 주제, 원본 출처, 실제 촬영·자료 사진·일러스트 구분을 기록합니다. 승인된 보관함에서 주제에 맞는 사진을 고르고, 세 가지 편집 틀 중 하나로 제목과 설명을 합성합니다. 맞는 사진이 없으면 글자와 도형으로 된 설명 카드를 선택합니다. 무료 소재 서비스의 새 사진은 수동으로 선별해 보관함에 추가합니다.

현재 프로젝트에는 사진 크기 조절과 한글 제목 합성 코드가 있습니다. 이를 재사용할 수 있지만, 위의 사진 보관함·분류 선택·비교 카드 기능은 아직 구현하지 않았습니다.

초기에는 사진 중심 표지와 질문 중심 표지를 각각 몇 개 운영하고, 도달 대비 저장과 프로필 활동을 비교해 어느 형식이 맞는지 판단합니다. 작은 표본에서 형식 하나가 성과의 원인이라고 단정하지 않습니다.
