# 전체 검수 보고서 (2026-10-09)

인스타그램 API(`/api/instagram/*`, 게시·연결 코드, Graph API 호출)는 **실행하지 않고 제외**했습니다. 예약 게시가 *어떤 게시물을 고르는지*만 코드로 읽었습니다.

## 진행 상황

- **1순위(예약 안전) 고침 — 2026-10-09**: A-1(글 고치면 예약 풀림 알림·글 쓰는 중 예약 막기), A-2(올리기 직전 저장된 게시물 다시 확인·보관함 제외·지금 글로 올림, 목록 다시 읽는 중 저장 반영), A-3(게시물마다 저장 한 번에 하나씩), 예약 지연 안내 "최대 1시간쯤", 인스타 연결 없으면 "연결 전이라 안 올라가요", 내 게시물 상태 표시 갱신, 한 달 계획에서 보관함 제외, 잘못된 요청 500→400(게시물 경로).
- 2순위 이하: 아직.

## 0. 한 줄 요약

- 빌드·테스트는 모두 정상입니다(배포 빌드 성공, 단위 테스트 797개 통과, 화면 테스트 46개 통과).
- 하지만 **"화면에는 됐다고 나오는데 실제로는 다르게 동작하는" 곳이 몇 군데** 있습니다. 가장 큰 두 가지:
  1. **예약 후 글을 고치면 예약이 몰래 풀리는데 화면은 계속 "○시에 올라가요"** → 안 올라감.
  2. **카드 글자 수를 맞추느라 문장을 앞에서 잘라 "따라 향의 세기가 달라요" 같은 반쪽 문장이 카드에 찍힘** → 특히 AI가 실패해 기본 문안으로 만들 때 거의 항상.

## 1. 검수 방법

| 영역 | 방법 |
|---|---|
| 배포 빌드 | `next build` 실제 실행 → 성공 |
| 단위 테스트 | 전체 실행 → 797 통과 (1개 실패는 PowerShell 없는 환경 탓, 기존과 같음) |
| 화면 테스트 | 전체 실행 → 46 통과 |
| 타입·린트 | 오류 0 (경고 3개, 모두 테스트 설정 파일) |
| 6개 영역 정밀 검수 | 주제 추천 / 만들기 과정 / 카드 그리기 서버 / 저장·예약·내 게시물 / 로그인·설정·사진함 / 버튼 하나하나 추적 |
| 확인 방식 | 의심 항목마다 임시 테스트로 **실제로 재현**(확인됨) 또는 코드로만 판단(의심) 구분. 카드는 실제로 그려서 눈으로 봄 |

## 2. 꼭 고쳐야 할 것 (게시가 안 되거나, 이상한 게시물이 나감)

### A-1. 예약 후 글을 고치면 예약이 풀리는데, 화면은 "올라가요" 그대로 — **확인됨**
- 3단계에서 예약 → 올릴 글을 한 글자라도 고치면 1.2초 뒤 자동 저장되면서 서버가 예약을 끔(바뀐 글은 다시 확인받으려는 장치).
- 그런데 예약 칸은 그 사실을 다시 읽지 않아 "○월 ○일 저녁 6:00에 올라가요"를 계속 보여 줌 → **사장님은 예약된 줄 알고 끄지만 안 올라감.**
- `글 다시 쓰기`를 예약 뒤에 눌러도 같음. 예약 버튼이 글 쓰는 중에도 눌림.
- 위치: `ReviewStep.tsx`(예약 칸 key), `ScheduleShare.tsx`, `DraftWizard.tsx` 자동 저장, `repository.ts` saveCaption
- 고칠 방향: 글이 저장되면 예약 상태를 다시 읽고, 풀렸으면 "글을 고쳐 예약이 풀렸어요 · 다시 예약하기"를 보여 줌. (또는 글만 바뀐 경우 예약 유지)

### A-2. 예약을 취소했는데도 올라갈 수 있는 짧은 틈 — **확인됨(시간 틈이 좁음)**
- 예약 게시는 가벼운 "목록 요약"만 보고 올릴 게시물을 고르는데, 이 요약은 10분마다 저장소에서 다시 읽습니다. **다시 읽는 도중에 취소·보관하면 그 취소가 최대 10분 무시**될 수 있음.
- 게시 단계도 전체 게시물을 다시 보고 "최종 확인·보관 여부"를 재확인하지 않고, 요약에 있던 **글**을 그대로 올림.
- 위치: `drafts/repository.ts` 요약 캐시, `instagram/scheduler.ts`(코드만 읽음), `instagram/publish.ts`
- 고칠 방향: 올리기 직전에 전체 게시물을 다시 읽어 "예약 켜짐·시간 맞음·보관 아님"을 확인하고 그 게시물의 글로 올림. (※ 인스타 API 호출 부분은 건드리지 않고, 고르는 조건만 고치면 됨)

### A-3. 동시에 저장되면 예약·보관이 덮어써짐 — **확인됨(드묾)**
- 글 자동 저장과 예약 저장이 거의 동시에 일어나면, 늦게 끝난 쪽이 게시물 전체를 덮어써 예약이 사라지거나 보관한 게시물이 다시 예약될 수 있음.
- 고칠 방향: 저장할 때 마지막 수정 시각을 확인(다르면 다시 읽고 반영), 예약·보관 전 자동 저장 대기열 비우기.

### A-4. 홍보 카드를 못 그리면, 마지막 장이 "넘겨 보기" 표시 그대로 끝남 — **확인됨**
- 모든 장을 "뒤에 홍보 카드가 붙는다"고 보고 그리는데, 홍보 카드가 실패하면 그냥 빠진 채 저장 → 게시물 마지막 장에 "넘겨 보기 >"가 있는데 넘길 장이 없음.
- 장 고치기 화면은 "홍보 카드를 그리는 중…"이 영원히 표시.
- 고칠 방향: 실패하면 홍보 카드 없이 마지막 장을 "마지막 장"으로 다시 그리기.

## 3. 결과물이 의도와 다르게 나오는 것

### B-1. 카드 문장이 앞에서 잘려 반쪽 문장이 됨 — **확인됨(직접 재현)**
글자 수 제한(사진 중심 제목 18자·짧은 글 24자, 글 중심 14자·18자)을 넘으면 코드가 문장을 자르는데, 주어나 이유가 날아갑니다.

| 원래 문장 | 카드에 찍힌 것 |
|---|---|
| 홍어는 삭힌 정도에 따라 향의 세기가 달라요 | 따라 향의 세기가 달라요 |
| 미나리전은 바삭할 때 먹어야 향이 살아 있어요 | 미나리전은 바삭할 때 |
| 왜 홍어는 막걸리와 함께 먹으면 더 맛있을까요? | 먹으면 더 맛있을까요? |
| 홍어 처음 드시는 분께 알려 드리는 한 점 먹는 순서 (표지) | 분께 알려 드리는 한 점 먹는 순서 |

- **AI가 실패해 기본 문안을 쓸 때는 거의 매번** 이렇게 나옵니다(기본 문안 자체가 글자 수 제한보다 김). 글 중심 기본 문안 예: "놓으면 더 잘 어울려요", "이것만 확인하면 돼요".
- 위치: `track.ts` fitLine / splitHeadline / fitTrackCopy, `carousel.ts` 기본 문안

### B-2. 문구 검수 AI가 글자 수 문제를 볼 기회가 없음 — **확인됨**
- 구성안을 받으면 **먼저 글자 수대로 잘라 놓고** 그다음 검수 AI에게 보내서, 검수 AI는 이미 잘린 문장만 봄. 그래서 "본문 제목은 질문 대신 답으로"(어제 넣은 규칙)도 질문이 둘로 쪼개지면서 검사에 안 걸림.
- 고칠 방향: 검수를 먼저(잘리기 전 문장으로), 자르기는 마지막 안전장치로. 기본 문안은 글자 수 안으로 다시 쓰기.

### B-3. 사진 1장만 올리면 5장 중 2장이 글자만 있는 장 — **확인됨**
- "사진이 모자란 장은 AI가 사진을 참고해 그려요"라고 안내하지만, 실제로는 사진 1장당 최대 2장까지만 AI가 채우고 나머지는 글자 카드. (사진 2장 이상이면 모두 채워짐)
- 고칠 방향: 사진 중심이면 비어 있는 장은 모두 AI가 채우기.

### B-4. AI 그림이 실패해도 사장님은 모름 — **확인됨**
- 크레딧 부족 등으로 AI 장면을 못 그리면 조용히 확대 사진·글자 카드로 대체. "3~5분" 기다렸는데 왜 그림이 없는지 알 수 없음.
- 한 장이 실패해 "다시 해 보기"를 누르면 **이미 그린 AI 그림을 버리고 다시 그려 크레딧이 두 번** 들 수 있음.

### B-5. 사진으로 주제를 정한 뒤에도 그 사진이 계속 추천에 끼어듦 — **확인됨**
- 사진으로 주제를 고르고 다음 단계로 넘어가면 사진은 화면에서 사라지는데, 사진 정보는 남아 이후 "다른 주제 보기"·"새로 만들기"도 계속 그 사진 기준으로 추천.

### B-6. 직접 쓴 주제가 추천에 덮어써짐 — **확인됨**
- 주제를 직접 써 둔 상태에서 "다른 주제 보기"나 사진 넣기를 누르면, 새 추천의 첫 주제로 바뀌어 직접 쓴 글이 사라짐.
- 한 달 계획에서 가져온 주제도 같은 방식으로 바뀌면서 계획 날짜 연결까지 끊김.

### B-7. "넣은 사진을 보고 고른 주제예요"가 사실이 아닐 때가 있음 — **확인됨**
- 사진을 못 읽었을 때(키 없음) 파일 이름("IMG_1234")으로 추천하는데도 같은 문구. 이때 메뉴 고르게 규칙까지 꺼져 삼합 주제만 둘 나오기도 함.
- AI가 사진과 상관없는 주제를 줘도 그대로 받아들이고, AI 실패 시 준비된 주제 3개 중 사진 메뉴는 최대 1개.

### B-8. AI 그림을 나중에 추가해도 "AI 연출 이미지" 안내가 글에 안 붙음 — **확인됨(코드)**
- 안내 문구는 글을 쓸 때만 붙음. 확인 화면에서 AI 장을 새로 넣으면 안내 없이 올라갈 수 있음.

## 4. 화면·안내가 실제와 다른 것

| 내용 | 상태 |
|---|---|
| 예약 안내 "1~2분 늦을 수 있어요" ↔ 실제 깨우기는 1시간마다 → **최대 1시간 늦을 수 있음** (설정 화면엔 "5분마다"라고 또 다르게 적힘) | 확인됨 |
| 내 게시물에서 날짜 저장 뒤 상태 표시(예약됨 등)가 안 바뀜 | 확인됨 |
| 이미지 모음의 "새로 만들기"가 새로 시작이 아니라 지난 게시물을 다시 엶 | 확인됨 |
| 내 게시물에서 다시 연·복제한 게시물은 "이 장 다시 만들기·글자 고치기·홍보 카드"가 사라짐(도움말엔 된다고 적힘) | 확인됨 |
| 다시 연 게시물에서 장을 넣고 빼면 장 번호가 안 맞음 | 확인됨(코드) |
| 사진 저장 실패 시 "'다시 해 보기'를 눌러 주세요" → 그 화면엔 그런 버튼 없음, 미리보기와 서버 사진이 달라짐 | 확인됨(코드) |
| 글 저장 실패 시 "잠시 뒤 다시 저장해요" → 실제로 다시 저장 안 함 | 확인됨(코드) |
| 2단계에서 이전으로 돌아가 다른 주제를 고르면 넣어 둔 사진이 묻지 않고 사라짐 | 확인됨 |
| 인스타 연결 없이 "최종 확인"을 켜면 "예약됨"으로 보이지만 안 올라감 | 확인됨(코드) |
| 반응 기록 "기록 지우기" 뒤 저장하면 지운 숫자가 다시 저장됨 | 확인됨 |
| 한 달 계획 화면에 보관함 게시물도 "확인 필요"로 나옴 | 확인됨 |
| 설정의 "캐러셀 장수"는 아무 데도 안 쓰임(어려운 말도 남음) | 확인됨 |

## 5. 그 밖의 것 (덜 급함)

- **로그인 잠금**: 누군가 틀린 비밀번호를 100번 넣으면 사장님도 15분간 로그인 못 함(반복 가능). 접속 주소 판별도 위조 가능. — 확인됨
- **Gemini 키가 틀렸을 때** "키가 맞지 않아요" 대신 "연결에 문제" 로 안내. — 확인됨(코드)
- **설정 읽기가 실패한 상태에서 설정을 저장하면** 다른 설정이 기본값으로 덮어써질 수 있음. — 확인됨(코드)
- 잘못된 요청이 들어오면 일부 서버 경로가 400 대신 500 오류. — 확인됨
- 사진 보관함: 글자 카드 미리보기만 해도 "사용 횟수"가 올라감. 안 쓰는 업로드 경로가 남아 저장 공간을 씀.
- "설탕·탕후루" 같은 말을 홍어애탕으로 착각. 10월 과메기 주제에 "가을" 표시. 설날·추석 날짜표 2030년까지.
- 작은(카톡으로 받은) 사진에서 카드 사진에 네모 얼룩이 생기는 경우 — 확인됨(원인은 추정)
- 서버 쪽 패키지 버전이 모두 "latest"라 나중에 설치할 때 큰 버전이 갑자기 바뀔 수 있음.

## 6. 정상으로 확인된 것 (주요)

- 모든 서버 경로(인스타 제외)가 로그인한 사장님만 쓰게 막혀 있음. 게시물·사진 번호 검사, 경로 조작 막힘.
- 키가 없거나 AI가 안 될 때 멈추지 않고 준비된 주제·기본 문안으로 이어짐.
- 사진 1장~여러 장, 사진 없음, 글 중심/사진 중심 모두 5장이 만들어지고 저장·글쓰기까지 이어짐.
- AI 장의 "AI 연출 이미지" 안내(만들 때), 사진 참고 방식이 세 이미지 AI 모두에서 실제로 전달됨.
- 카드에 글자 넘침·겹침 없음, 장 번호·넘겨 보기·홍보 카드 모양 정상.
- 예약 빠른 시각(오늘/내일 점심·저녁) 한국 시간 계산 정확. 보관함 넣기·꺼내기, 복제, 탭 개수 정상.
- 계절·행사·복날·설/추석(2025~2030) 날짜, 네이버 검색어 캐시, 추천 간격 대기 정상.
- 큰 휴대폰 사진(5천만~2억 화소) 처리 정상.
