# 간소화 계획: 50대 사장님이 버튼 몇 번으로 끝내는 앱

## 왜 바꾸나
- 무엇이 좋은지 모르는 상태에서 고를 것이 너무 많다(이미지 단계에만 방식 4·디자인 계열 21·테마 8·계절 소품 8·글꼴 11·화풍 3·파노라마…).
- 화면에 어려운 말이 30곳 넘게 나온다(캐러셀, 구성안, 계열, 화풍, 슬라이드, 요점, 캡션, 누끼, 크레딧, 문안, 해시태그 조합…).
- 사장님은 무언가를 하나하나 고르는 것을 번거로워하신다. 앱이 정하고, 사장님은 확인만 하게 한다.
- 디자인 계열마다 사진 장이 한 모양이라 틀이 다 같아 보였다. 계열을 늘리는 대신 **두 갈래로 정리**한다.

## 정한 것(사용자 결정, 2026-10-08)
- 템플릿은 두 갈래: **사진 중심**, **글 중심**.
  - 글 중심: 장마다 글 **3줄 이내**(제목 1줄 + 짧은 줄 2개까지), 큰 글씨.
  - 사진 중심: 사진을 그냥 붙이지 말고 **퀄리티 높게**(보정·여백·글자 처리까지 공들인 한 가지 고급 모양).
- 사진을 안 올리면 **AI가 그려 준다**(사진 중심 5장은 시간이 걸린다고 안내).
- 장 수는 **자동 고정**: 두 갈래 모두 5장(+ 맨 뒤 가게 홍보 카드는 자동). 글 중심은 표지 한 장만 그림이 있어 빨리 끝난다.
- 자주 안 쓰는 기능(한 달 기획, 성과 기록, 콘텐츠 자료, 사진 보관함 관리, 장 넣기·빼기, 글자 직접 고치기 세부 등)은 지우지 않고 **'더보기'에 숨긴다**.
- 게시는 큰 버튼 두 개: **인스타그램에 바로 올리기**, **휴대폰에 저장하기**.

## 새 순서(3단계)
1. **무엇을 올릴까요?** 추천 주제 3개 중 하나를 누르거나 직접 쓴다. 배지는 "이번 철" 하나만(독자 유형·검색 증가율 숫자 없음).
2. **어떻게 만들까요?** 큰 카드 두 개 중 하나(📷 사진 중심 / ✏️ 글 중심) + "사진 올리기(선택)" + **만들기** 한 번.
   - 그다음은 자동: 구성 → 그림(사진이 있으면 사진, 없으면 AI) → 표지 자동 선택 → 모든 장 → 글(본문·# 태그)까지.
   - 기다리는 동안 무엇을 하는 중인지 쉬운 말로 한 줄, 진행 막대.
3. **확인하고 올리기**: 사진과 글을 한 화면에서 본다. 버튼은 "글 고치기", "이 장 다시 만들기", 그리고 큰 게시 버튼 두 개.

## 화면에서 없애는 것(코드는 숨김·자동으로)
- 이미지 방식 4개(무료 카드·실제 사진·AI·사진+AI) → 사진 유무로 자동.
- 디자인 계열·테마·계절 소품·글꼴·화풍·"장마다 자동/사진 위 글자" 선택 → 갈래가 정한다.
- 표지 후보 2장 고르기, 표지 수정 요청 → 자동(필요하면 "이 장 다시 만들기").
- 파노라마, 홍보 카드 켜기/끄기 → 자동(홍보 카드는 늘 붙임, 끄기는 더보기).
- 문안 단계의 첫 문장 후보·부분 다시 만들기 4개 → "글 다시 쓰기" 하나.
- 확인 단계의 내보내기 4개·복사 2개·해시태그 묶음·음악 방향·게시 순서 → 게시 버튼 두 개 + "글 복사".
- 메뉴: **만들기 / 내 게시물 / 설정** + 더보기(한 달 기획·성과·콘텐츠 자료·사진 보관함·도움말).
- 설정의 기술 항목(Instagram 서버 설정, 저장소, AI 연결·사용량, 원격 누끼, AI 선택)은 "관리자용" 접힘 안으로.

| 캐러셀 | 게시물 사진(5장) / 사진 묶음 |
| 슬라이드 | 장 |
| 문안 | 글 |
| 구성안 | (화면에서 없앰) |
| 요점 | 짧은 글 |
| 해시태그 | # 태그 |
| 캡션 | 글 |

- 오류·안내 문장은 "무엇을 누르면 되는지"만 짧게. 기술 이름(Gemini, Supabase, API, 환경변수)은 관리자용에만.
- 글자는 크게(본문 18px 이상), 버튼은 크게(높이 52px 이상), 한 화면에 큰 버튼은 하나가 주인공.

## 기술 방향
- 새 디자인 두 개: `styles/photoFocus.ts`, `styles/textFocus.ts`(StyleId `photo-focus`, `text-focus`). 예전 계열 코드는 저장된 게시물을 다시 열 때를 위해 남긴다.
- 생성 상태에 `track: "photo" | "text"`. 구성안 요청에 갈래를 넘기고, 갈래가 디자인·장 수·글 길이를 정한다(무작위 섞기 끔).
- 글 길이는 프롬프트와 코드 모두에서 지킨다(글 중심 3줄, 사진 중심 제목 1줄 + 짧은 줄 1개).
- 저장된 예전 게시물(다른 계열·장 수)은 그대로 열리고 다시 그려진다.

## 진행 단계
- A. 두 갈래 디자인 + 구성안 규칙(갈래·장 수·글 길이) — 샘플 그림으로 확인.
- B. 화면 순서 3단계·자동 진행·확인 화면·메뉴·설정·말 바꾸기·큰 글씨.
- C. 도움말·운영 문서·테스트(단위·화면) 정리, 전체 검토(만드는 중인 게시물 지키기·죽은 코드 정리 포함).

## A 단계 결과(2026-10-08)
- 디자인: `styles/photoFocus.ts`(사진 중심: 꽉 찬 표지, 본문은 "액자"·"꽉 찬 사진"을 장마다 번갈아, 마지막 장은 사진 + 가게 명함), `styles/textFocus.ts`(글 중심: 사진 카드 표지, 본문은 큰 장 번호 + 제목 한 줄 + 짧은 글 두 줄, 크림 → 겨자 → 밤색 바탕, 마지막 장은 큰 원형 로고 명함). 공용 색·로고·바닥글은 `styles/trackKit.ts`.
- 두 계열은 갈래만 고른다: 구성안 AI 안내문·무작위 섞기·한 달 기획·화면의 계열 고르기에는 나오지 않는다(`styleCatalog.ts`의 `TRACK_STYLES`·`PICKABLE_STYLES`).
- 구성안: `/api/images/plan`에 `track: "photo" | "text"`를 주면 5장, 갈래 디자인, 장마다 사진 수(글 중심은 표지만 사진), 글 길이(표지 24·20자, 사진 중심 제목 18자 + 짧은 글 1개 24자, 글 중심 제목 18자 + 짧은 글 2개 각 20자)를 프롬프트와 코드(`track.ts`의 `applyTrack`) 모두에서 맞춘다. 갈래가 없으면 예전과 같다.
- 생성 상태: `GenerationInput.track`이 있으면 구성안 요청에 실린다. 화면 연결(B 단계)과 사장님 사진 묶음(`photoCarousel.ts`가 사진 수에 맞춰 레이아웃을 바꾸는 부분)의 갈래 처리는 아직이다.
- 샘플 시트: `scripts/render-track-samples.mjs --out=폴더`(표지·본문 3장·마지막 장 × 어두운/밝은 사진 × 보통/긴 글, 자동 검수 결과 출력).
- 검토 수정(2026-10-08): 글 줄이기가 꾸밈말·관형형·의존 명사 뒤에서 시작하지 않게(“톡 / 쏘는”, “덜 삭힌 / 홍어”, “오시기 / 전에” 방지), 제목 줄바꿈은 한 글자 낱말을 다음 낱말과 묶음(“홍어 한 / 점이” 방지), “가기 전에”를 전(부침) 메뉴로 오인해 흰 회 사진에 윤기 보정이 걸리던 문제 수정, 글 중심 마지막 장 로고 뒤 원이 계정 글자를 가리던 문제 수정, 갈래 없는 요청에 AI가 갈래 계열을 적어 와도 쓰지 않음, 갈래 초안은 한 달 기획 추천 계열이 덮어쓰지 않음. 샘플 시트는 구성안과 같은 글 길이 맞추기를 거친 글로 그린다.

## B 단계 결과(2026-10-08)
- 디자인 손보기: 글 중심 본문 장의 글을 키웠다(제목 84~112px, 짧은 글 62px, 큰 장 번호 300px). 장 번호와 글을 바닥글 위 남는 높이의 가운데에 두어 글 아래 빈 띠가 330px → 250px대로 줄었다. 큰 글자에서도 한 줄씩 들어가게 글 중심 글 길이를 제목 14자·짧은 글 18자로 줄였다(`track.ts`, 프롬프트·코드 모두).
- 화면 3단계(`DraftWizard`·`MakeStep`·`ReviewStep`·`PhotoPicker`): 1 무엇을 올릴까요(추천 A·B·C + 이번 철 배지, 직접 쓰기, 다음) → 2 만들기(📷 사진 중심 / ✏️ 글 중심 + 사진 올리기(선택) + 만들기, 걸리는 시간 한 줄) → 3 확인하고 올리기(미리보기·글 칸·글 다시 쓰기·이 장 다시 만들기, 큰 버튼 두 개, 더보기). 예전 문안 단계·이미지 방식 4개·계열/테마/계절/글꼴/화풍/레이아웃 고르기·표지 후보·파노라마·참고 방식 화면은 지웠다(`ImageStudio`·`PhotoCarouselStudio`·`CopyEditor`·`PostPreview`).
- 자동 진행(`generationStore.createAutomatically`): 구성안(갈래) → 그림(사진 묶음 또는 AI, 글 중심은 표지 후보 2장 중 표지 점검 1등, 사진 중심은 1장) → 나머지 장 → 홍보 카드 → 저장 → 글 쓰기·저장. 한 줄 안내 + 진행 막대(`autoProgress`), 다른 화면에 다녀와도 계속, 멈추면 쉬운 말 + 다시 해 보기(멈춘 곳부터). 주제를 바꾸면 그 만들기를 멈춘다(`cancelGeneration`).
- 사장님 사진 갈래 처리(`photoCarousel.ts`): 사진 중심은 장마다 사진 1장까지, 글 중심은 첫 장만 사진(본문 0장, 같은 사진 다시 쓰기 없음).
- 메뉴: 만들기·내 게시물·설정 + 더보기(한 달 계획(새 `/plan`)·콘텐츠 자료·이미지 모음·도움말). 내 게시물 카드의 올릴 날짜·반응 적기는 접어 두고, 달력·반응 돌아보기는 한 달 계획 화면으로 옮겼다.
- 설정: 인스타그램 연결(서버 설정 목록 없이)과 브랜드 키트만 보이고, 나머지는 접힌 관리자용 설정 안. 장 수 설정은 예전 방식에만 쓰인다.
- 말: 초안→게시물, 문안→글, 요점→짧은 글, 해시태그→# 태그, 계열·테마 표시 없앰. 오류는 무엇을 누를지만, 기술 이름은 관리자용에만(자세한 이유는 접어서).
- 크기: 기본 글자 18px, 주인공 버튼 56~64px, 휴대폰 360px 점검 통과(`mobile-layout.spec.ts`).
- 예전 게시물: 저장된 사진·글 그대로 3단계로 열린다(구성안이 없어 이 장 다시 만들기는 숨김). 글 없이 사진만 있으면 열면서 글을 써 준다.
- 문서·테스트: 도움말·운영 안내서·README 갱신. 단위 테스트(자동 진행·갈래 사진 배치·설정·메뉴)와 화면 테스트(e2e)를 새 흐름으로 바꿨다.
- 검토 수정(2026-10-08): 인스타그램이 연결되지 않으면 흐린 '바로 올리기'도 주인공 색을 내려놓아 주인공 버튼이 '휴대폰에 저장하기' 하나가 되게, 바로 올리기가 서버에서 막히면 쉬운 한 줄 + '휴대폰에 저장하기' 안내(서버 이유는 접어서), caption 없이 copy만 있는 아주 예전 게시물은 그 글을 이어 보여 주고 저장(새 글로 덮어쓰지 않음), AI 그림이 멈추면 '가게 사진을 올려 보세요' 안내, 만드는 중 화면의 '· 0초' 숨김, 설정의 '계정 저장'은 보조 버튼. 휴대폰 360px·PC에서 단계별 화면(사진 중심/글 중심 × 사진 있음/없음, AI 실패 뒤 다시 해 보기, 다른 메뉴 다녀오기, 글 쓰기 실패, 연결 전/연결 후/올리기 실패, 예전 게시물 4종)을 다시 찍어 확인했다.

## C 단계 결과(2026-10-08)
- 만드는 중인 게시물 지키기: 만들기는 화면 밖(`generationStore`)에서 돌아서, 만드는 동안 다른 게시물을 열거나 새로 시작하면 소리 없이 멈출 수 있었다(특히 1단계로 돌아갔다가 다른 메뉴에 다녀오면 새 추천 주제가 골라져 만들던 것이 끊겼다). 이제
  - 만드는 중에 다른 추천 카드·아예 다른 주제를 적고 `다음`·`새로 만들기`·내 게시물의 `열기`/`복제해서 고치기`/`같은 주제로 새로`/`새로 만들기`·한 달 계획의 다른 주제로 시작하기를 누르면 “지금 만드는 게시물이 있어요. 그만두고 새로 시작할까요?”라고 묻는다. 취소하면 만들던 것이 그대로 이어지고(주제 칸도 되돌림), 확인하면 그 만들기를 멈춘다(늦게 끝나도 저장 안 함). 같은 게시물을 여는 것은 묻지 않고, 복제는 묻고 나서 복제본을 만든다(`confirmStopGeneration`, `KeepRunningLink`, 화면이 새로 열릴 때 주소를 보고 한 번 더 확인).
  - 만드는 중에 `만들기` 메뉴를 누르면 언제든 진행 화면으로 돌아온다(자동 만들기가 게시물 정보 `auto.meta`를 들고 있어 탭 세션이 1단계여도 같은 게시물로 돌아감). 만드는 중에는 3단계로 건너뛰지 않는다.
  - 이미 다 만든 게시물에서 `만들기`를 다시 누르면 “이미 만든 게시물이 있어요. 처음부터 다시 만들까요? 그림을 새로 만들어요.”라고 묻는다(멈춘 뒤 `다시 해 보기`는 묻지 않음).
- 단계 표시: 폭 520px 이하에서는 `1 주제 · 2 만들기 · 3 올리기`로 한 줄, 넓은 화면은 긴 이름 그대로. 버튼 이름(화면 읽기·시험)은 폭과 상관없이 긴 이름.
- 내 게시물 카드: 주인공 버튼 `열기` 하나 + 작은 `더보기`(복제해서 고치기·같은 주제로 새로·지우기, 지우기는 한 번 더 물음). 맨 위 `새로 만들기`는 보조 버튼.
- 죽은 코드 정리: 예전 이미지 화면만 쓰던 생성 상태·함수(방식 고르기, 계열·테마·계절·글꼴·화풍·레이아웃 고르기, 파노라마, 사진+AI 참고 사진, 표지 후보 고르기·수정 요청, 구성안만 따로 만들기, 사진 순서 바꾸기·사진 그대로 쓰기, 보이지 않던 안내 문구 상태)를 지우고, 그것만 시험하던 시험(파노라마 사진 바꾸기, 글꼴·테마·계열 덮어쓰기, 참고 사진 방식 등)도 지웠다. 이 장 다시 만들기·장 고치기·글자 고치기·글자 카드·예전 게시물 열기는 그대로. 서버의 파노라마 그리기(API)는 남겨 둔다.
- 화면 시험 서버(`scripts/e2e-server.mjs`): 시작할 때 30분보다 오래됐고 주인 프로세스가 없는 `e2e-app-*` 복사본을 지운다(강제로 멈춘 실행이 하나에 200MB씩 남겨 26GB까지 쌓였다). 경로 안전 확인은 그대로.
- 말: 사장님에게 보이는 서버 안내(게시물 열기·복제·지우기·날짜 저장·인스타그램 올림 상태·한 달 계획)에서 초안→게시물, 문안→글, 희망일시→올릴 날짜로 바꿨다. 기술 이름·AI 프롬프트·관리자용 설정·접힌 “자세한 이유”는 그대로.
- 문서·시험: 운영 안내서·도움말 갱신, 단위 시험(만드는 중 지키기 6개, 짧은 단계 이름, 내 게시물 링크·복제 취소), 화면 시험(만드는 중 열기 취소·확인, 휴대폰 단계 한 줄, 카드 더보기).
- 검토 수정(2026-10-08): 메모 없이 직접 쓴 주제로 만들던 중 아예 다른 주제를 적고 `다음`에서 "확인"을 눌러도 바뀐 것이 없다고 보고 만들기를 멈추지 않아, 옛 주제의 그림이 새 주제 게시물에 붙던 문제를 고쳤다(확인하면 직접 새 게시물로 바꾼다). 1단계에서 단계 표시줄의 `2 만들기`나 같은 화면의 `만들기` 메뉴로 가면 묻지 않고 주제만 바뀌던 옆길도 `다음`과 같은 확인을 거치게 했다(만드는 중이면 `만들기` 메뉴가 같은 화면 안에서도 진행 화면으로 데려간다). 휴대폰 360px·PC에서 단계별 화면을 다시 찍어 확인했다.
