# 간소화 계획: 50대 사장님이 버튼 몇 번으로 끝내는 앱

## 왜 바꾸나
- 무엇이 좋은지 모르는 상태에서 고를 것이 너무 많다(이미지 단계에만 방식 4·디자인 계열 21·테마 8·계절 소품 8·글꼴 11·화풍 3·파노라마…).
- 화면에 어려운 말이 30곳 넘게 나온다(캐러셀, 구성안, 계열, 화풍, 슬라이드, 요점, 캡션, 누끼, 크레딧, 문안, 해시태그 조합…).
- 사장님은 무언가를 하나하나 고르는 것을 번거로워하신다. 앱이 정하고, 사장님은 확인만 하게 한다.
- 디자인 계열마다 사진 장이 한 모양이라 틀이 다 같아 보였다. 계열을 늘리는 대신 **두 갈래로 정리**한다.

## 정한 것(사용자 결정, 2026-10-08)
- 템플릿은 두 갈래: **사진 중심**, **글 중심**.
  - 글 중심: 장마다 글 **3줄 이내**(제목 1줄 + 짧은 줄 2개까지), 큰 글씨.
  - 사진 중심: 사진을 그냥 붙이지 말고 **퀄리티 높게**(보정·여백·글자 처리까지 공들인 한 가지 고급 모양).
- 사진을 안 올리면 **AI가 그려 준다**(사진 중심 5장은 시간이 걸린다고 안내).
- 장 수는 **자동 고정**: 두 갈래 모두 5장(+ 맨 뒤 가게 홍보 카드는 자동). 글 중심은 표지 한 장만 그림이 있어 빨리 끝난다.
- 자주 안 쓰는 기능(한 달 기획, 성과 기록, 콘텐츠 자료, 사진 보관함 관리, 장 넣기·빼기, 글자 직접 고치기 세부 등)은 지우지 않고 **'더보기'에 숨긴다**.
- 게시는 큰 버튼 두 개: **인스타그램에 바로 올리기**, **휴대폰에 저장하기**.

## 새 순서(3단계)
1. **무엇을 올릴까요?** 추천 주제 3개 중 하나를 누르거나 직접 쓴다. 배지는 "이번 철" 하나만(독자 유형·검색 증가율 숫자 없음).
2. **어떻게 만들까요?** 큰 카드 두 개 중 하나(📷 사진 중심 / ✏️ 글 중심) + "사진 올리기(선택)" + **만들기** 한 번.
   - 그다음은 자동: 구성 → 그림(사진이 있으면 사진, 없으면 AI) → 표지 자동 선택 → 모든 장 → 글(본문·# 태그)까지.
   - 기다리는 동안 무엇을 하는 중인지 쉬운 말로 한 줄, 진행 막대.
3. **확인하고 올리기**: 사진과 글을 한 화면에서 본다. 버튼은 "글 고치기", "이 장 다시 만들기", 그리고 큰 게시 버튼 두 개.

## 화면에서 없애는 것(코드는 숨김·자동으로)
- 이미지 방식 4개(무료 카드·실제 사진·AI·사진+AI) → 사진 유무로 자동.
- 디자인 계열·테마·계절 소품·글꼴·화풍·"장마다 자동/사진 위 글자" 선택 → 갈래가 정한다.
- 표지 후보 2장 고르기, 표지 수정 요청 → 자동(필요하면 "이 장 다시 만들기").
- 파노라마, 홍보 카드 켜기/끄기 → 자동(홍보 카드는 늘 붙임, 끄기는 더보기).
- 문안 단계의 첫 문장 후보·부분 다시 만들기 4개 → "글 다시 쓰기" 하나.
- 확인 단계의 내보내기 4개·복사 2개·해시태그 묶음·음악 방향·게시 순서 → 게시 버튼 두 개 + "글 복사".
- 메뉴: **만들기 / 내 게시물 / 설정** + 더보기(한 달 기획·성과·콘텐츠 자료·사진 보관함·도움말).
- 설정의 기술 항목(Instagram 서버 설정, 저장소, AI 연결·사용량, 원격 누끼, AI 선택)은 "관리자용" 접힘 안으로.

## 말 바꾸기
| 지금 | 바꿀 말 |
|---|---|
| 캐러셀 | 게시물 사진(5장) / 사진 묶음 |
| 슬라이드 | 장 |
| 문안 | 글 |
| 구성안 | (화면에서 없앰) |
| 요점 | 짧은 글 |
| 해시태그 | # 태그 |
| 캡션 | 글 |
| 초안 | 게시물(만드는 중) |
| 디자인 계열·테마·화풍 | (화면에서 없앰) |
- 오류·안내 문장은 "무엇을 누르면 되는지"만 짧게. 기술 이름(Gemini, Supabase, API, 환경변수)은 관리자용에만.
- 글자는 크게(본문 18px 이상), 버튼은 크게(높이 52px 이상), 한 화면에 큰 버튼은 하나가 주인공.

## 기술 방향
- 새 디자인 두 개: `styles/photoFocus.ts`, `styles/textFocus.ts`(StyleId `photo-focus`, `text-focus`). 예전 계열 코드는 저장된 게시물을 다시 열 때를 위해 남긴다.
- 생성 상태에 `track: "photo" | "text"`. 구성안 요청에 갈래를 넘기고, 갈래가 디자인·장 수·글 길이를 정한다(무작위 섞기 끔).
- 글 길이는 프롬프트와 코드 모두에서 지킨다(글 중심 3줄, 사진 중심 제목 1줄 + 짧은 줄 1개).
- 저장된 예전 게시물(다른 계열·장 수)은 그대로 열리고 다시 그려진다.

## 진행 단계
- A. 두 갈래 디자인 + 구성안 규칙(갈래·장 수·글 길이) — 샘플 그림으로 확인.
- B. 화면 순서 3단계·자동 진행·확인 화면·메뉴·설정·말 바꾸기·큰 글씨.
- C. 도움말·운영 문서·테스트(단위·화면) 정리, 전체 검토.
