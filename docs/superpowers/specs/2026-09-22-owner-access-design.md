# 1인 관리자 로그인 설계

작성일: 2026-09-22
상태: 사용자 승인 완료 (2026-09-22)

## 목적과 범위

이 앱은 당분간 묵동홍어마을 운영자 1명만 사용한다. 로컬 주소뿐 아니라 ngrok 등으로 외부에 열었을 때도 초안, 이미지, AI 생성 기능, 설정, Instagram 연결·게시 기능을 익명 방문자가 사용할 수 없게 한다. 기존 초안 데이터와 명시적인 게시 승인 절차는 그대로 유지한다.

이번 단계에서는 직원 계정, 회원가입, 암호 재설정 메일, 역할별 권한, 자동 게시·예약을 만들지 않는다.

## 사용자 경험

1. 미로그인 사용자가 앱 화면에 접근하면 간단한 `관리자 로그인` 화면으로 이동한다. 설명은 “이 앱을 사용하는 관리자 암호를 입력하세요” 수준으로 짧게 둔다.
2. 관리자는 설치 시 서버 환경변수로 준비한 암호를 입력한다. 로그인에 성공하면 원래 열려던 화면으로 돌아간다. 실패 시 암호가 틀렸다는 일반적인 안내만 보이며, 계정·서버 구성 정보를 노출하지 않는다.
3. 상단 메뉴에 `로그아웃`을 둔다. 세션이 만료되거나 로그아웃하면 다음 요청부터 다시 로그인해야 한다. 세션은 최대 8시간이며 브라우저를 닫아도 그 시간 내에는 유지될 수 있음을 안내한다.
4. 필요한 로그인 설정이 빠진 서버에서는 익명 사용 모드로 전환하지 않는다. 로그인 화면에 설정 필요 안내를 표시하고, 보호 대상 API는 사용할 수 없게 한다.

암호는 채팅이나 웹 UI에서 초기 설정하지 않는다. 서버 운영자가 입력 내용이 화면·명령 기록에 남지 않는 로컬 설정 도구로 해시를 만들고 `OWNER_PASSWORD_HASH`에 저장한다. 세션 암호화 키 `AUTH_SECRET`도 별도로 만든다. 두 값 모두 저장소·클라이언트 번들·로그에 포함하지 않는다. `.env.example`에는 값이 아닌 설정 방법만 넣는다.

## 인증 방식과 경계

- Auth.js Credentials를 사용해 1개의 고정 관리자 신원을 인증하고, 서버에서 세션을 확인한다. 실제 구현에 앞서 이 프로젝트의 Next.js 16.3.4와 호환되는 버전을 고정하고 테스트한다.
- 암호는 서버에서 안전한 해시와 비교한다. 원문 암호는 디스크에 저장하지 않는다. 로그인 실패 메시지는 동일하게 처리하고, 실패 횟수 제한을 둔다. 외부 공개 배포 시에는 앱 프로세스의 메모리 제한만 믿지 않고 ngrok 또는 배포 진입점의 지속적인 요청 제한도 설정·검증한다. 그 제한이 준비되지 않으면 공개 URL을 배포 완료로 표시하지 않는다.
- 세션 쿠키는 `HttpOnly`, HTTPS에서 `Secure`, `SameSite=Lax`로 사용한다. 세션 기간은 8시간 이내로 제한한다. 암호 유출·변경 시 `AUTH_SECRET`을 교체해 기존 세션을 모두 무효화하는 운영 절차를 문서화한다.
- Next.js Proxy는 로그인 화면 이동과 빠른 거절에만 사용한다. 각 보호 대상 Route Handler와 서버에서 데이터를 읽는 화면에서도 세션을 검증한다. 따라서 프런트엔드 버튼을 우회해 API 주소를 직접 호출해도 접근할 수 없다.
- 보호 대상은 `/`, `/drafts`, `/settings`와 모든 콘텐츠·설정·Instagram API다. 현재 API 기준으로 `/api/topics`, `/api/images/*`, `/api/copy`, `/api/media/upload`, `/api/drafts`, `/api/export/*`, `/api/settings`, `/api/instagram/connect`, `/api/instagram/connection`, `/api/instagram/status`, `/api/instagram/publish`가 포함된다. 앞으로 새 Route Handler를 만들 때도 기본적으로 보호한다.
- 비로그인 예외는 로그인 처리 경로, 정적 자산, `/api/instagram/callback`, `/api/media/public/[draftId]`뿐이다. Instagram 콜백은 기존의 일회성 OAuth `state` 검증을 통과해야 하며, 연결 시작은 로그인 상태에서만 가능하다. 공개 미디어는 기존의 서명·만료 검증을 통과해야 하며, 다른 초안이나 파일을 열 수 없다. 예외 경로라는 이유로 검증을 생략하지 않는다.
- 로그인 후 원래 경로로 돌아갈 때 내부 경로만 허용해 외부 URL로 보내는 리다이렉트는 막는다. 인증·초안·설정 응답은 공유 캐시에 저장하지 않는다.

## 기존 흐름과의 관계

저장된 초안과 선택 이미지, 문안은 이 작업으로 이동하거나 삭제하지 않는다. 로그인 뒤에는 기존의 `주제 → 이미지 → 문안 → 확인`, `내 초안`, 설정, ZIP 내보내기 흐름을 그대로 이용한다. Instagram 연결이나 게시를 대신 실행하지 않는다. 게시 버튼의 최종 사용자 승인 검증은 로그인 검증과 별도로 유지한다.

서명된 이미지 URL은 Instagram 서버가 이미지를 가져오기 위해 잠시 공개되어야 한다. 이 경로는 로그인 쿠키를 요구하지 않지만, 유효한 서명과 만료 시간을 요구한다. 그러므로 공개 미디어 URL을 일반 공유 링크처럼 취급하거나 로그에 남기지 않는다.

## 검증 기준

- 익명 사용자는 보호 화면에서 로그인 화면으로 이동하고, 보호 API의 직접 호출은 `401` 또는 인증 목적의 명확한 응답을 받는다. 서버 설정 누락은 `503`으로 구분한다.
- 올바른 관리자 암호는 로그인과 화면 복귀가 되고, 틀린 암호와 반복 실패는 제한된다. 로그아웃한 브라우저는 재접근할 수 없고, 만료·서버 비밀키 교체 뒤의 이전 세션은 거절된다. 탈취된 쿠키까지 즉시 무효화하려면 비밀키 교체가 필요하다는 한계를 운영 문서에 명시한다.
- 로그인 상태에서 기존 초안 읽기·수정, 이미지 생성, 문안 생성, 내보내기, Instagram 연결 상태 확인이 회귀 없이 동작한다. 게시 요청은 로그인만으로 승인되지 않고 기존 명시적 승인 조건을 통과해야 한다.
- 공개 미디어의 정상 서명 URL만 지정된 시간에 해당 이미지를 반환한다. 누락·변조·만료된 URL은 실패한다. OAuth 콜백의 잘못된 `state`도 실패한다.
- 로컬 개발과 실제 공개 URL에서 화면·API·쿠키·로그아웃을 직접 확인한다. 자동 테스트 통과만으로 공개 환경 검증을 완료했다고 표시하지 않는다.

## 배포 전 준비와 남는 위험

운영자는 관리자 암호와 `AUTH_SECRET`을 안전하게 생성해 서버 환경변수에 넣고 앱을 재시작해야 한다. HTTPS와 외부 진입점의 로그인 시도 제한이 확인될 때까지 ngrok 또는 배포 URL을 타인에게 공유하지 않는다. 단일 암호 방식은 운영자 1명에게만 적합하며, 직원이 별도 계정으로 사용하기 시작하면 계정·권한·감사 기록을 다시 설계해야 한다.
