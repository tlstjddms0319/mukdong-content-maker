# 음식 소개 Instagram 캐러셀 설계

작성일: 2026-09-17
상태: 사용자 승인 완료

## 목적

선택한 게시물 주제를 실제 이미지 생성 요청까지 전달하고, 같은 프롬프트의 대안 사진이 아니라 역할과 구도가 다른 음식 소개 캐러셀을 만든다. 기본은 5장이며 결과는 초안 저장, 최종 미리보기, ZIP 내보내기, 명시적 승인 후 Instagram 게시까지 한 세트로 유지한다.

## 기본 사용자 흐름

1. 사용자가 주제를 고르거나 직접 입력한다.
2. `AI 이미지 생성` 또는 `사진 + AI 함께`를 고른다.
3. Gemini가 선택 주제와 이미지 설명을 바탕으로 구성안을 만든다. 기본은 5장이며 설정에서 3장, 5장, 7장, 10장을 고를 수 있다.
4. OpenAI가 표지 후보 2장을 만들고 사용자가 하나를 고른다.
5. 앱이 나머지 4장을 역할별로 순서대로 만들며 `2/5`, `3/5`처럼 실제 진행 상태를 표시한다.
6. 앱이 생성 이미지 위에 정확한 한글 제목과 슬라이드 번호를 합성한다. 이미지 모델에는 한글 렌더링을 맡기지 않는다.
7. 사용자가 설정된 장수를 모두 확인하고 한 세트로 승인한다.
8. 승인된 세트만 초안에 저장되고 문안 단계로 진행한다.

실제 사진만 사용하는 방식은 기존처럼 단일 이미지 게시물로 유지한다. 혼합 방식에서는 업로드한 사진을 음식 형태의 기준으로 사용하고 나머지 흐름은 캐러셀과 동일하다.

## 5장 기본 구성

| 순서 | 역할 | 시각적 목적 |
|---|---|---|
| 1 | 표지 | 완성 한상 또는 핵심 음식의 강한 히어로 컷과 주제 훅 |
| 2 | 핵심 디테일 | 표지와 다른 거리에서 재료, 결, 윤기 같은 질감 강조 |
| 3 | 먹는 법 | 젓가락이나 손동작으로 한 점을 만드는 과정 |
| 4 | 추천 조합 | 막걸리, 모임, 날씨 등 선택 주제와 연결된 상황 |
| 5 | 방문 유도 | 실제 한상과 편안한 분위기, 묵동홍어마을 방문 행동 안내 |

각 장은 새 정보를 제공해야 한다. 같은 원거리 상차림을 다섯 번 반복하지 않는다. 전체 세트는 색온도, 그릇, 테이블 재질, 녹색 포인트를 공유하되 촬영 거리와 각도는 의도적으로 바꾼다.

설정에서 장수를 바꾸면 기본 흐름을 다음처럼 축약하거나 확장한다.

- 3장: `표지 → 먹는 법 → 방문 유도`
- 5장: 위 표의 기본 구성
- 7장: `표지 → 전체 상차림 → 디테일 → 먹는 법 → 추천 조합 → 먹는 상황 → 방문 유도`
- 10장: 7장 구성에 `준비 과정 → 분위기 → 최종 행동 안내`를 추가

자동 게시 호환성을 위해 10장을 넘기지 않는다.

## 캐러셀 구성 데이터

Gemini는 설정된 장수와 역할 순서에 정확히 맞는 계획만 반환한다.

- `styleAnchor`: 전 장에 공통으로 적용할 색감, 조명, 그릇, 테이블 기준
- `slideCount`: `3`, `5`, `7`, `10` 중 하나
- `slides`
  - `role`: 장수별로 정해진 역할 중 하나
  - `headline`: 앱이 합성할 짧은 한국어 제목
  - `visualPrompt`: 이미지 모델에 보낼 장면 설명
  - `textPosition`: `top` 또는 `bottom`

응답이 없거나 형식이 틀리면 같은 장수의 앱 기본 계획으로 자동 대체한다. Gemini가 선택한 주제나 확인되지 않은 가격, 원산지, 영업정보를 바꿀 수 없다.

## 이미지 생성 규칙

- OpenAI 이미지 요청에는 `topic`, 기존 `imageBrief`, 해당 장의 `role`, `visualPrompt`, `styleAnchor`, `textPosition`을 함께 보낸다.
- 표지만 `n=2`로 대안을 만들고 나머지는 서로 다른 프롬프트로 `n=1`씩 만든다.
- 결과는 모두 1080×1350, 4:5, JPEG로 정규화한다.
- 이미지 모델에는 글자, 로고, 가격표, 확인되지 않은 매장 외관이나 손님 얼굴을 만들지 말라고 명시한다.
- 앱은 Sharp로 어두운 그라데이션, 한글 제목, `현재/전체` 번호를 합성한다.
- AI 생성 또는 편집 출처는 슬라이드마다 보존한다.

## 저장과 호환성

- `media_candidates`에는 승인된 슬라이드를 순서대로 저장한다.
- 새 `selected_media_ids`에는 게시 순서대로 ID를 저장한다.
- 기존 `selected_media_id`는 첫 장인 표지 ID를 계속 저장해 기존 단일 이미지 초안과 호환한다.
- 이전 초안에 `selected_media_ids`가 없으면 `selected_media_id` 한 장만 선택된 것으로 읽는다.
- 선택 ID는 모두 `media_candidates`에 존재해야 하고 첫 ID는 `selected_media_id`와 같아야 한다.

## 미리보기와 내보내기

- 최종 확인 화면은 이전·다음 버튼, 현재 번호, 썸네일로 모든 슬라이드를 확인할 수 있어야 한다.
- 피드의 대표 썸네일은 항상 첫 장을 사용한다.
- `전체 묶음 받기` ZIP에는 `slide-01.jpg`부터 `slide-05.jpg`, `caption.txt`, 순서와 출처가 들어간 `metadata.json`을 포함한다.
- `표지 이미지 받기`는 첫 장만 바로 내려받는다.

## Instagram 게시

- 1장이 선택된 기존 초안은 현재 단일 이미지 게시 흐름을 사용한다.
- 2~10장이 선택된 초안은 각 이미지를 공개 서명 URL로 제공하고 child container를 만든 뒤, 그 ID들로 parent carousel container를 만든다.
- 서명에는 `draftId`, `mediaId`, 만료 시각을 모두 포함해 다른 슬라이드에 재사용할 수 없게 한다.
- 문안은 parent carousel에만 붙인다.
- 기존의 `승인하고 Instagram에 게시` 클릭, 승인 값 재검증, 중복 게시 방지는 그대로 유지한다.
- 사용자의 명시적 클릭 없이 생성이나 저장의 부수 효과로 게시하지 않는다.

## 오류와 복구

- 표지 생성 실패 시 주제와 업로드 사진을 보존하고 표지만 다시 시도한다.
- 뒤 슬라이드 생성 실패 시 이미 완성된 장을 보존하고 실패한 순서부터 다시 시도한다.
- 설정된 장수가 모두 준비되기 전에는 캐러셀 승인 버튼을 활성화하지 않는다.
- 저장 실패 시 문안 단계로 진행하지 않는다.
- 캐러셀 게시 중 child 생성이 하나라도 실패하면 parent 생성과 publish를 실행하지 않는다.

## 접근성과 화면 원칙

- 모든 선택과 이동은 키보드 버튼으로 가능해야 한다.
- 현재 표지, 현재 슬라이드, 생성 진행 수를 텍스트와 `aria` 상태로 제공한다.
- 모바일 320px 이상에서 가로 페이지 넘침 없이 슬라이드 영역만 스크롤할 수 있어야 한다.
- 새 캐러셀 라이브러리는 추가하지 않고 React 상태와 CSS로 구현한다.

- 동영상 또는 Reel 캐러셀

- 슬라이드별 자유 편집기와 드래그 정렬
- 성과 기반 자동 A/B 최적화

## 완료 기준

- 선택한 주제와 이미지 설명이 모든 이미지 요청에 전달된다.
- 표지 2개가 서로 비교 가능하고, 승인한 표지가 첫 장으로 유지된다.
- 다섯 장의 역할과 프롬프트가 서로 다르다.
- 생성 중 실제 완료 장수가 보인다.
- 기본 5장이 순서대로 저장, 복원, 미리보기, ZIP 내보내기 되며 설정의 3·7·10장도 같은 흐름을 사용한다.
- 단일 이미지 초안은 이전처럼 동작한다.
- Instagram 캐러셀은 명시적 승인 후 child 5개, parent 1개, publish 1회로 처리된다.
- 단위 테스트, lint, build, 데스크톱·모바일 핵심 E2E가 통과한다.
