# 연동 후순위: 사용 가능한 앱 틀 완성 설계

작성일: 2026-09-24
상태: 구현 전 검토 요청

## 목적과 경계

묵동홍어마을 운영자가 메뉴를 눌렀을 때 막히지 않고, 초안을 만들고 다시 찾아 수정하는 웹앱의 기본 틀을 완성한다. 새 외부 서비스 연결보다 현재 화면의 완결성과 설명의 정확성을 우선한다. 기존 주제·이미지·문안 AI 연결과 4단계 제작 흐름은 유지한다. Supabase 설정, Meta 계정 연결·자동 게시, 실시간 인기 검색어 API, 신규 AI 제공자 연결은 이번 작업에 포함하지 않는다. 이미 구현된 연동 코드나 저장 데이터는 삭제하지 않는다.

이 설계는 [초기 웹앱 설계](2026-09-10-instagram-draft-webapp-design.md)의 쉬운 기본 사용·이미지 우선 원칙을 이어받는다. 현재 구현과 달라진 부분은 실제 작동 여부를 분명히 표시하는 화면 설계다.

## 완료 기준

1. 상단 메뉴의 `새 초안`, `내 초안`, `이미지 제작실`, `콘텐츠 자료`, `설정`, `도움말`이 모두 실제 화면으로 연결되고 1인 로그인 보호를 받는다.
2. 화면의 주 버튼은 현재 가능한 동작을 수행한다. 아직 적용되지 않는 기능은 클릭 가능한 설정처럼 보여주지 않고 `추후 적용`으로 설명한다.
3. 사용자는 기존 4단계 흐름에서 주제 선택, 사진 업로드 또는 AI 이미지 선택, 문안 확인, 저장·재편집·다운로드를 계속 할 수 있다.
4. 사용자가 업로드한 사진, 선택 이미지, 문안, 기존 초안은 새 화면 작업 때문에 지워지거나 덮어써지지 않는다.
5. 메뉴·빈 화면·오류·진행 중 상태가 초보 사용자에게 짧은 한국어로 이해된다. 작동하지 않은 검사를 `완료`로 표시하지 않는다.

## 화면별 경험

| 화면 | 사용자가 보는 것 | 주요 동작 | 데이터와 경계 |
| --- | --- | --- | --- |
| `/` 새 초안 | 기존 4단계 제작 화면과 단계 이동 | 주제 선택 → 이미지 → 문안 → 확인 | 현재 초안 흐름과 승인 지점을 그대로 사용한다. |
| `/drafts` 내 초안 | 저장된 초안과 재편집 진입점 | 초안 다시 열기 | 기존 저장소를 사용하고 저장 방식에 따라 지속성이 달라질 수 있음을 안내한다. |
| `/images` 이미지 제작실 | 실제 사진·AI 이미지·혼합 방식의 짧은 설명, 저장된 초안의 이미지 미리보기 | `이미지 제작 시작`으로 기존 새 초안 흐름 열기, 해당 초안 열기 | 별도 생성기나 두 번째 이미지 저장소를 만들지 않는다. 이미지가 없으면 빈 상태와 시작 버튼을 보여준다. |
| `/library` 콘텐츠 자료 | 미리 준비한 홍어·가게 소개 주제 카드와 촬영·문안 힌트 | `이 주제로 초안 시작` | 정적·로컬 자료다. 실시간 인기 주제처럼 표시하지 않는다. 사실 확인이 필요한 가게 정보는 단정하지 않는다. |
| `/settings` 설정 | 현재 작동하는 옵션과 연결 상태, 추후 옵션 안내 | 작동하는 설정만 변경·저장 | 이번 범위의 실제 적용 옵션은 캐러셀 장수와 이미지 AI 선택이다. 저장은 기존 설정 체계를 사용한다. |
| `/help` 도움말 | 4단계 사용법, 저장·재편집·다운로드, AI 비용·오류 대처, 자동 게시 범위 | 관련 화면으로 이동 | 비밀키나 개인 데이터는 노출하지 않는다. |

### 이미지 제작실

이미지 제작실은 독립 생성 화면이 아니라 기존 초안 제작의 이미지 중심 입구다. 상단에는 `실제 사진 사용`, `AI 이미지 생성`, `사진+AI` 세 방식을 한 문장씩 설명한다. 그 아래 기존 초안 저장소에서 선택된 표지와 슬라이드를 읽어 최근 결과를 보여준다. 표지나 슬라이드를 누르면 해당 초안 편집으로 이동한다. 이미지가 없는 초안은 제목과 `이미지 미선택` 상태로만 보여주고 깨진 미리보기는 만들지 않는다. `이미지 제작 시작`은 `/`의 주제 단계로 이동하며, 이미지 단계에 바로 진입한다고 약속하지 않는다. 이는 이미지 생성 전 주제와 내용이 필요하기 때문이다.

### 콘텐츠 자료

콘텐츠 자료는 여러 방향의 주제 시작점을 제공한다. 예시는 `처음 먹는 사람을 위한 안내`, `삼합을 즐기는 순서`, `막걸리와 함께하는 이유`, `동네 식사 장면`, `실제 메뉴 사진으로 소개`처럼 서로 다른 이야기 각도를 포함한다. 카드는 제목, 한 줄 의도, 추천 이미지 장면, 확인할 사실 한 가지를 담는다. 사용자가 카드를 선택하면 새 초안 화면에 주제만 미리 채운다. 카드 내용은 완성 게시물이나 실시간 트렌드가 아니다.

새 초안 URL의 주제값은 120자 이내 일반 텍스트로 제한한다. 기존 초안 ID가 URL에 있으면 기존 초안 복원이 우선한다. 라이브러리 카드로 `새 초안 시작`을 명시적으로 눌렀을 때만 새로운 작업으로 진입하며, 이전에 저장한 초안은 변경하지 않는다. 주제 미리 채우기는 저장이나 AI 요청을 자동 실행하지 않는다.

### 설정의 정직한 표현

현재 화면에 있는 여러 설정 중 실제 제작 경로가 소비하는 `캐러셀 장수`와 `이미지 AI`만 수정 가능한 설정으로 둔다. 이미지 방식·비율·후보 수·문안 길이·문안 AI·안전 체크박스처럼 현재 저장은 되지만 결과에 반영되지 않는 항목은 조작 가능한 입력에서 제외하고 `추후 적용할 옵션`으로 짧게 설명한다. 기존 저장값은 보존하며 스키마나 기본값을 임의 변경하지 않는다. `기본값 복원`은 두 활성 옵션만 복원하고, 버튼 옆에 그 범위를 표시한다. API 키는 서버 환경변수 상태만 보여주며 값은 표시하지 않는다. 연결 상태 문구도 `키가 설정됨`과 `실제 요청 성공`을 혼동하지 않는다.

Meta/Instagram 관련 항목은 현재 연결을 완료해야 기본 앱을 쓸 수 있다는 인상을 주지 않는다. 이 단계에서는 `게시 연동은 추후 단계`로 안내한다. 기존 게시 기능과 보호 장치는 변경하지 않는다.

### 도움말과 작은 상호작용

도움말 첫 화면은 `주제 선택 → 이미지 선택 → 문안 확인 → 저장/다운로드` 네 줄로 시작한다. 사진과 AI 이미지의 차이, 여러 장 슬라이드, 초안 다시 찾기, 비용이 발생할 수 있는 AI 호출, 인터넷/키 문제 시 사진을 직접 올리는 대안을 짧게 설명한다. Instagram 자동 게시와 실시간 트렌드 수집은 현재 기본 제작 단계에 포함되지 않는다고 분명히 쓴다.

기존 문안 화면의 동작 없는 분위기 버튼은 제거한다. 확인 화면의 정적 체크 표시는 실제 검사 결과가 아닐 경우 `확인할 항목`으로 바꾼다. 중요한 이미지 생성에는 단계별 진행 문구와 오류 후 재시도/사진 사용 경로를 유지한다.

## 구현 구조와 데이터 흐름

- 공통 내비게이션은 기존 `WizardShell`을 재사용하고 활성 메뉴·현재 위치를 명확히 표시한다. 화면별 스타일은 현재 디자인 토큰과 카드/버튼 패턴을 따른다.
- 새 페이지는 기존 페이지와 같은 1인 로그인 보호를 사용한다. 새 공개 API는 만들지 않는다.
- `/images`는 기존 초안 저장소의 읽기 결과만 사용한다. 이미지 생성·선택·저장은 `DraftWizard`/`ImageStudio` 경로 한 곳에서만 수행한다.
- `/library`의 카드 자료는 한 곳에 정의된 로컬 데이터다. 외부 API나 주기적 수집, 새 데이터베이스가 없다.
- 새 초안의 주제 미리 채우기는 사용자 입력처럼 검증하고, 저장된 초안 재개와 충돌하지 않게 한다.
- 모바일에서는 메뉴와 카드가 줄바꿈·세로 배치되어 주요 버튼을 가리지 않는다. 키보드 포커스, 버튼 이름, 이미지 대체 텍스트를 제공한다.

## 실패·빈 상태

- 초안이 없을 때 `/drafts`와 `/images`는 `아직 저장된 초안이 없어요`와 시작 버튼을 보여준다.
- 일부 초안에 이미지가 없거나 이미지 파일을 읽을 수 없어도 나머지 목록은 표시한다.
- 로그아웃 상태의 보호 화면은 `/login`으로 이동하고, 로그인 후 원래 화면으로 돌아온다.
- 저장소 장애는 빈 목록으로 위장하지 않고 재시도 가능한 오류로 표시한다.
- AI 실패는 기존 사진 업로드/직접 문안 수정 경로를 막지 않는다.

## 검증 범위

1. 모든 메뉴 링크가 실제 보호된 페이지로 연결되는지 확인한다.
2. 초안이 없는 상태와 이미지가 없는 초안 상태를 확인한다.
3. 콘텐츠 카드에서 주제가 미리 채워지고, 기존 저장 초안을 열 때 덮어쓰지 않는지 확인한다.
4. 설정에서 활성 항목만 수정 가능하며 비활성 항목이 작동한다고 오해할 표현이 없는지 확인한다.
5. 기존 주제→이미지→문안→확인, 초안 재편집, 다운로드를 회귀 점검한다.
6. 정적 검사·빌드와 데스크톱/모바일 화면 확인을 각각 수행한다. 빌드 성공만으로 실제 브라우저 동작을 검증했다고 말하지 않는다.

## 이번에 하지 않는 일

Supabase 프로젝트 생성·마이그레이션, Meta OAuth·게시 활성화, 예약 게시, 실시간 인기 검색어 수집, 신규 AI 모델 연결, 요금제 변경, 별도 이미지 생성 파이프라인, 다중 사용자 계정은 후속 단계다. 현재 앱의 저장 방식과 외부 연결 상태를 사실대로 설명하되, 이 작업에서 해결된 것처럼 표시하지 않는다.

## 구현 순서 제안

1. 빈 메뉴를 실제 화면으로 연결하고 콘텐츠 자료에서 기존 제작 흐름으로 진입시킨다.
2. 설정과 장식성 버튼의 작동 여부를 정리해 화면의 약속과 실제 동작을 일치시킨다.
3. 로그인·빈 상태·기존 초안 흐름·모바일을 점검하고 사용 안내를 맞춘다.

이 문서 승인 후 세부 구현 계획과 검증 절차를 작성한다.
