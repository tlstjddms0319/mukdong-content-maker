# Instagram 연결 및 승인 게시 설계

작성일: 2026-09-11  
상태: 사용자 검토 대기

## 1. 목적과 범위

묵동 콘텐츠 메이커에서 완성한 게시물 초안을 가게의 Instagram 프로페셔널 계정에 연결하고, 사용자가 최종 승인한 경우에만 게시한다.

이번 구현 범위는 다음과 같다.

1. 설정 화면에서 Instagram 계정을 연결하거나 연결 상태를 확인한다.
2. Meta OAuth 콜백을 검증하고 토큰을 서버 전용 저장소에 보관한다.
3. 최종 확인 화면에서 사용자가 명시적으로 승인한 단일 이미지 게시물을 전송한다.
4. 게시 준비, 성공, 실패 상태와 복구 방법을 쉬운 한국어로 표시한다.
5. 같은 초안의 중복 게시를 차단한다.

예약 게시, 릴스, 스토리, 캐러셀, 댓글 관리, 성과 분석은 이번 범위에서 제외한다.

## 2. 사용자 흐름

### Instagram 연결

- 설정의 `Instagram 연결` 버튼을 누르면 Meta가 제공하는 Instagram 로그인 화면으로 이동한다.
- 앱은 `instagram_business_basic`과 `instagram_business_content_publish` 권한만 요청한다.
- 콜백 성공 후 계정 이름과 연결 상태만 화면에 표시한다.
- 토큰, 앱 비밀키, 전체 API 응답은 브라우저에 전달하지 않는다.
- 계정이 비즈니스 또는 크리에이터 계정이 아니면 전환 방법을 안내하고 연결을 완료하지 않는다.

### 승인 게시

- 최종 확인 화면은 기존 다운로드 버튼을 유지한다.
- Instagram이 연결되고 게시 가능한 이미지가 준비된 경우에만 `승인하고 Instagram에 게시` 버튼을 활성화한다.
- 버튼 바로 위에 게시될 계정, 이미지, 문안 요약을 다시 보여준다.
- 사용자가 버튼을 누른 동작 자체를 최종 승인으로 간주하며, 자동 선택이나 페이지 진입만으로 게시하지 않는다.
- 게시 요청 중에는 버튼을 잠그고 생성 컨테이너 준비와 게시 완료 상태를 구분해 표시한다.
- 성공하면 Instagram 게시물 ID와 게시 시간을 저장한다.
- 실패하면 초안은 보존하고 재시도 또는 설정 이동 중 하나를 안내한다.

## 3. 서버 구조

### 연결 API

- `GET /api/instagram/status`: 연결 여부와 표시 가능한 계정 정보만 반환한다.
- `GET /api/instagram/connect`: 일회성 OAuth state를 쿠키에 저장하고 Meta 로그인 URL로 이동한다.
- `GET /api/instagram/callback`: state와 code를 검증하고 토큰을 교환한 뒤 계정 정보를 저장한다.
- `DELETE /api/instagram/connection`: 연결 정보만 삭제한다. 구현 시 사용자 확인을 요구한다.

### 게시 API

- `POST /api/instagram/publish`: 초안 ID와 명시적 승인값을 받는다.
- 서버가 저장된 초안, 선택 이미지, 문안, Instagram 연결 상태를 다시 검증한다.
- 공개 이미지 URL로 미디어 컨테이너를 생성한 뒤 준비 상태를 확인하고 게시한다.
- 초안별 idempotency 기록을 확인해 이미 성공한 게시물을 다시 올리지 않는다.

Meta API 호출과 토큰 처리는 `src/features/instagram/` 아래의 서버 전용 모듈이 담당한다. UI 컴포넌트는 내부 토큰이나 Meta 전용 응답 구조를 알지 못한다.

## 4. 저장 구조

`data/instagram/connection.json`에는 서버에서만 읽는 다음 정보를 저장한다.

- Instagram 사용자 ID
- 표시용 사용자 이름
- 액세스 토큰
- 토큰 만료 시각
- 부여된 권한
- 연결 및 갱신 시각

`data/instagram/publications/<draft-id>.json`에는 게시 상태를 저장한다.

- 초안 ID
- 상태: `preparing`, `published`, `failed`
- Meta 미디어 컨테이너 ID
- 게시된 미디어 ID
- 마지막 오류의 안전한 분류
- 시도 및 완료 시각

파일 저장은 현재 설정·초안 저장소와 동일하게 임시 파일 작성 후 rename하는 원자적 방식을 사용한다.

## 5. 공개 이미지 경계

Meta 게시 API는 게시 시점에 외부에서 접근 가능한 이미지 URL을 요구한다. 로컬 `data/media` 경로나 `data:` URL은 직접 게시할 수 없다.

- 개발 단계에서는 게시 어댑터를 모의 처리해 승인 흐름을 검증한다.
- 실제 게시 활성화 전에는 배포 환경과 비공개 원본/공개 게시물 파생본을 구분하는 객체 저장소를 선택한다.
- 공개 URL은 임시 서명 URL을 우선하며 게시 완료 후 만료시킨다.
- 단일 이미지 게시용 파생본은 JPEG로 만들고 4:5 비율을 유지한다.

## 6. 보안

- `INSTAGRAM_APP_SECRET`과 토큰은 서버 전용이며 클라이언트 번들, 로그, 초안, 내보내기 파일에 포함하지 않는다.
- OAuth state는 예측 불가능한 값으로 생성하고 짧은 수명의 HttpOnly, SameSite=Lax 쿠키로 검증한다.
- 콜백의 redirect URI는 환경변수의 고정값과 정확히 일치시킨다.
- 게시 API는 `approved: true`가 없으면 거절한다.
- 연결 만료, 권한 부족, 이미지 접근 실패, 게시 제한을 서로 다른 안전한 오류로 변환한다.
- API 응답이나 오류 객체 전체를 사용자 화면과 로그에 출력하지 않는다.
- `.env.example`에는 플레이스홀더만 두고 실제 값은 `.env.local` 또는 배포 환경의 비밀 저장소에만 둔다.

## 7. 설정과 환경변수

필수 환경변수:

- `INSTAGRAM_APP_ID`
- `INSTAGRAM_APP_SECRET`
- `INSTAGRAM_REDIRECT_URI`

실제 게시 단계에서 추가할 환경변수:

- 공개 미디어 저장소 자격 증명
- 공개 미디어 기본 URL 또는 버킷 정보

설정 화면은 `연결 안 됨`, `연결됨`, `다시 연결 필요` 세 상태만 보여준다. 설정값이 없으면 연결 버튼 대신 Meta 앱 준비 안내를 표시한다.

## 8. 오류와 복구

- Meta 앱 미설정: 필요한 환경변수 이름과 설정 위치를 안내한다.
- OAuth 취소: 기존 초안과 설정을 유지하고 다시 연결 버튼을 보여준다.
- state 불일치: 연결을 중단하고 처음부터 다시 시도하도록 안내한다.
- 토큰 만료: 게시하지 않고 다시 연결을 요청한다.
- 공개 이미지 준비 실패: 다운로드 기능은 유지하고 게시만 재시도하게 한다.
- Meta 처리 지연: 컨테이너 상태를 제한된 횟수로 확인하고 계속 처리 중임을 표시한다.
- 중복 게시 요청: 기존 성공 결과를 반환하며 새 게시물을 만들지 않는다.

## 9. 테스트와 완료 기준

- 저장소 테스트가 토큰 저장과 원자적 갱신을 검증한다.
- OAuth 테스트가 state 불일치와 안전한 콜백 처리를 검증한다.
- API 테스트가 브라우저 응답에 토큰과 앱 비밀키가 없음을 검증한다.
- 게시 서비스 테스트가 컨테이너 생성, 완료 확인, 게시, 중복 차단 순서를 검증한다.
- 컴포넌트 테스트가 미연결 상태와 연결 상태의 버튼을 검증한다.
- Playwright 테스트가 데스크톱과 모바일에서 연결 상태 표시와 명시적 승인 게시 흐름을 모의 Meta API로 완주한다.
- 모든 자동 테스트는 실제 Meta 게시나 외부 API 비용을 발생시키지 않는다.

## 10. 구현 순서와 활성화 게이트

1. 연결 저장소와 안전한 상태 API
2. 설정 화면 연결 카드와 OAuth 시작·콜백
3. 게시 서비스와 중복 방지 기록
4. 최종 화면의 승인 게시 UI
5. 공개 미디어 저장소와 배포 환경 연결
6. 한 개의 테스트용 게시물로 실제 계정 검증

1~4는 Meta 자격 증명 없이 모의 API로 구현·검증할 수 있다. 5~6은 새 API 키 교체, Instagram 프로페셔널 계정 확인, Meta 앱 생성, 공개 배포 주소 준비가 완료된 뒤 활성화한다.
