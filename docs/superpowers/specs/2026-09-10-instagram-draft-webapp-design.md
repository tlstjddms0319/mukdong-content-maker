# 묵동 콘텐츠 메이커 웹앱 설계

작성일: 2026-09-10  
상태: 구현 계획 작성 전 최종 설계

## 1. 목적

묵동홍어마을 운영자가 전문적인 디자인·마케팅 지식 없이도 인스타그램 게시물 초안을 만들 수 있는 웹앱을 제작한다.

첫 버전의 완료 범위는 다음과 같다.

1. 게시물 주제를 선택하거나 직접 입력한다.
2. 실제 사진, AI 생성 이미지, 두 방식의 혼합 중 하나를 선택한다.
3. AI가 제목·본문·해시태그를 작성한다.
4. 사용자가 이미지와 문안을 확인하고 파일로 내려받는다.

Instagram 예약 준비, 사용자 승인 후 자동 게시, 실시간 트렌드 수집은 첫 버전에서 제외한다. 초안 제작 흐름이 안정된 뒤 단계별로 추가한다.

## 2. 핵심 원칙

### 쉬운 기본 사용

- 일반 화면에서는 한 번에 한 가지 결정만 요청한다.
- 사용자가 선택하지 않은 항목은 권장 기본값으로 자동 처리한다.
- 세부 설정은 별도 설정 화면에서만 노출한다.
- 설명은 짧고 쉬운 한국어로 표시한다.
- 모든 핵심 버튼은 한 가지 동작만 표현한다.

### 이미지 우선

- 이미지와 썸네일 품질을 제품의 최우선 기능으로 둔다.
- 실제 사진을 기본으로 권장한다.
- AI 이미지는 설명용 일러스트, 표지, 실제 사진의 보조 요소로 사용한다.
- 최종 이미지는 AI가 추천할 수 있지만 사용자가 직접 승인한다.
- 실제 메뉴의 양·재료·원산지·삭힘·매장 모습을 AI가 임의로 만들지 않는다.

### 사실과 출처 보호

- 가격, 영업시간, 휴무, 원산지, 메뉴 구성은 저장된 가게 정보만 사용한다.
- 확인되지 않은 정보가 필요하면 자동 생성하지 않고 확인 필요 상태로 표시한다.
- 일반 음식 정보와 묵동홍어마을의 실제 운영 정보를 분리한다.
- 실제 사진과 AI 생성·편집 이미지를 구분해 기록한다.
- 원본 사진은 수정하지 않고 결과물을 별도 파일로 만든다.

## 3. 대상 사용자

주 사용자는 콘텐츠 제작 도구에 익숙하지 않은 가게 운영자다.

- 긴 설정 설명보다 권장값을 선호한다.
- 휴대전화 사진을 바로 사용하려 한다.
- AI 결과가 맞는지 판단할 간단한 설명이 필요하다.
- 게시물 제작 후 Instagram 앱에서 직접 게시할 수 있다.

데스크톱과 모바일 브라우저를 모두 지원한다. 모바일에서도 주요 버튼과 입력 영역은 최소 44px 높이를 유지한다.

## 4. 사용자 흐름

### 1단계: 주제 선택

- AI 추천 주제 3개를 보여준다.
- 각 추천에는 제목, 한 줄 설명, 추천 이유를 제공한다.
- 사용자는 하나를 선택하거나 직접 주제를 입력한다.
- 선택하지 않고 넘어가면 첫 번째 권장 주제를 적용한다.

첫 버전의 추천은 마케팅 계획서와 저장된 콘텐츠 기둥을 기반으로 한다.

- 바다 음식 상식
- 발효와 조합
- 먹는 상황
- 동네 발견
- 가게의 실제

### 2단계: 이미지 선택과 제작

세 가지 방식을 제공한다.

1. 실제 사진 사용
2. AI 이미지 생성
3. 실제 사진과 AI 이미지 함께 사용

실제 사진 사용 시:

- 한 장 이상 업로드한다.
- 어두움·흔들림·해상도 부족을 점검한다.
- 원본을 보존하고 4:5 피드용 결과물을 만든다.
- AI가 제목 배치 공간과 중심 대상을 분석한다.

AI 이미지 생성 시:

- 게시물 목적에 맞는 후보 3장을 기본 생성한다.
- 후보마다 구도와 사용 목적을 짧게 설명한다.
- 사용자는 후보를 선택하거나 다시 생성한다.
- 고급 설정에서 표현 방식, 후보 수, 추가 요청을 바꿀 수 있다.

혼합 사용 시:

- 실제 사진이 음식과 매장의 증거 역할을 한다.
- AI는 안내 카드, 배경 정리, 설명용 일러스트를 보조한다.
- 실제 음식처럼 오인될 수 있는 생성 이미지는 사용하지 않는다.

### 이미지 품질 확인

이미지 후보마다 다음 항목을 확인한다.

- 작은 피드 썸네일에서도 중심 대상이 구분되는가
- 배경이 음식이나 문구를 방해하지 않는가
- 제목이 필요한 경우 충분한 여백이 있는가
- 4:5 잘림 이후에도 핵심 대상이 남는가
- 실제 사진, AI 생성, AI 편집 출처가 기록됐는가
- 실제 메뉴 정보와 어긋나는 시각 요소가 없는가

자동 검사는 참고 정보다. 합격 점수로 최종 이미지를 자동 확정하지 않는다.

### 3단계: 문안 생성과 편집

AI가 다음 결과를 하나의 편집 화면에 제공한다.

- 첫 문장
- 정보 설명
- 가게 연결 문장
- 행동 안내
- 해시태그
- AI 이미지 표시 문구가 필요한 경우 해당 문구

사용자는 전체 문안을 직접 수정하거나 다음 부분만 다시 생성할 수 있다.

- 첫 문장
- 가게 소개
- 행동 안내
- 해시태그

간단 조정 버튼은 `짧고 쉽게`, `조금 더 친근하게`, `정보를 더 자세히` 세 가지로 제한한다.

### 4단계: 최종 확인과 다운로드

- Instagram 게시물 형태의 미리보기를 표시한다.
- 작은 피드 썸네일을 별도로 보여준다.
- 이미지, 문안, 확인 필요 정보, 이미지 출처를 점검한다.
- `이미지 받기`, `문안 복사`, `전체 묶음 받기`를 제공한다.
- 전체 묶음에는 게시 이미지, 문안 텍스트, 생성 정보 JSON을 포함한다.
- 초안을 앱 안에 저장할 수 있다.
- 첫 버전에서는 실제 게시 기능을 제공하지 않는다.

## 5. 화면 구조

### 전역 메뉴

- 새 초안
- 내 초안
- 이미지 제작실
- 콘텐츠 자료
- 설정

데스크톱에서는 왼쪽 메뉴를 사용한다. 모바일에서는 상단 가로 메뉴로 바꾼다.

### 디자인 언어

- 배경: 따뜻한 아이보리 `#faf9f5`
- 기본 글자: 먹색 `#141413`
- 강조: 묵동홍어마을 짙은 녹색 `#1f5a43`
- 오류·위험 표시는 의미가 있을 때만 별도 색을 사용한다.
- 기본 본문은 16px 이상으로 유지한다.
- 제목은 한 화면에서 두 줄 이내를 우선한다.
- 버튼·입력은 10px, 주요 이미지·큰 영역은 14~16px 모서리를 사용한다.
- 그림자는 거의 사용하지 않고 여백과 얇은 구분선으로 계층을 만든다.
- 기본 전환은 100~200ms이며 움직임 줄이기 설정을 존중한다.

## 6. 설정

일반 사용자는 설정을 바꾸지 않아도 된다. 기본값은 다음과 같다.

| 항목 | 기본값 |
|---|---|
| 이미지 방식 | 실제 사진 우선 |
| AI 이미지 후보 | 3장 |
| 문안 길이 | 짧고 쉽게 |
| 이미지 비율 | 4:5 피드 |
| AI 제공자 | OpenAI |
| AI 모델 | 자동 선택 |
| 원본 사진 보존 | 켜짐 |
| 미확인 표현 차단 | 켜짐 |
| 정보 변경 시 재확인 | 켜짐 |

설정 구역은 다음과 같다.

- 기본 설정
- 가게 정보
- AI 연결
- 이미지 생성
- 문안
- 트렌드 연결
- 데이터 관리

API 키는 브라우저 저장소나 클라이언트 코드에 넣지 않는다. 서버 환경변수로만 읽고 화면에는 연결 상태만 표시한다.

## 7. AI 처리 구조

첫 버전은 OpenAI API 하나만 연결한다. 내부에서는 다음 역할을 분리한다.

1. `TopicService`: 저장된 가게 정보와 콘텐츠 기둥에서 주제를 제안한다.
2. `ImageService`: 이미지 분석·생성·편집 요청을 처리한다.
3. `CopyService`: 구조화된 게시물 문안을 생성한다.
4. `GuardService`: 금지 표현과 확인 필요 정보를 검사한다.

각 서비스는 앱 내부의 고정된 요청·응답 형식을 사용한다. OpenAI 전용 필드는 서비스 연결부 밖으로 노출하지 않는다. 다른 AI 제공자는 실제 필요가 생겼을 때 같은 형식의 연결부를 추가한다.

AI 문안 응답은 자유 텍스트가 아니라 다음 필드를 가진 구조화된 결과로 받는다.

- `topic`
- `audience`
- `hook`
- `information`
- `store_connection`
- `call_to_action`
- `hashtags`
- `facts_used`
- `facts_to_verify`
- `image_disclosure`

## 8. 데이터 구조

첫 버전은 한 명이 사용하는 로컬 웹앱으로 구현한다. 데이터는 로컬 앱 저장소에 보관하며 배포 단계에서 관리형 데이터베이스와 파일 저장소로 이전할 수 있도록 파일 경계를 분리한다.

### StoreProfile

- 상호
- 주소
- 전화
- 영업시간
- 휴무
- 위치 링크
- 확인일

### MenuItem

- 메뉴명
- 가격
- 실제 구성
- 원산지
- 확인된 향·식감 설명
- 판매 상태
- 확인일

### MediaAsset

- 원본 파일 위치
- 결과 파일 위치
- 실제 사진 / AI 생성 / AI 편집 구분
- 촬영·생성일
- 연결 메뉴
- 사용 동의
- 생성 설정

### Draft

- 선택 주제
- 대상 고객
- 이미지 후보와 선택 이미지
- 문안 구조
- 적용한 가게 정보 버전
- 확인 필요 항목
- 생성 상태
- 생성일·수정일

### AppSettings

- AI 제공자와 모델 선택 방식
- 기본 이미지 방식
- 후보 수
- 이미지 비율
- 문안 길이와 말투
- 보호 설정

## 9. 오류와 상태

모든 AI 작업은 다음 상태를 구분한다.

- 준비
- 생성 중
- 완료
- 확인 필요
- 실패

실패 시 전체 과정을 처음부터 다시 하지 않는다. 주제, 이미지, 문안 중 실패한 부분만 다시 요청한다.

- 이미지 생성 실패: 기존 후보를 보존하고 해당 후보만 다시 생성한다.
- 문안 생성 실패: 선택 이미지와 주제를 보존하고 문안만 다시 생성한다.
- API 인증 실패: 연결 문제를 설명하고 설정으로 이동한다.
- 파일 규격 실패: 원본을 보존하고 지원 형식을 안내한다.
- 저장 실패: 다운로드 가능한 결과를 먼저 제공하고 저장 실패를 알린다.

로딩 화면은 최종 결과와 같은 크기의 자리 표시를 사용한다. 빈 화면에는 다음 행동 하나를 명확하게 보여준다.

## 10. 보안과 개인정보

- API 키는 서버 환경변수에만 저장한다.
- 클라이언트에서 외부 AI API를 직접 호출하지 않는다.
- 업로드 파일 이름을 신뢰하지 않고 새 내부 식별자를 사용한다.
- 허용 확장자, MIME 유형, 크기를 서버에서 확인한다.
- 생성 결과와 원본을 다른 경로에 저장한다.
- 고객 얼굴이 포함된 사진은 사용 동의 상태를 기록한다.
- 로그에 API 키, 사진 원본, 개인 연락처를 남기지 않는다.

## 11. Graphify 활용

Graphify는 앱의 실시간 운영 데이터베이스로 사용하지 않는다. 프로젝트 지식과 변경 영향을 추적하는 개발 도구로 사용한다.

- 마케팅 계획서
- 확정 설계서
- 가게 정보 기준 문서
- 프롬프트와 금지 표현
- 화면 및 서비스 코드
- 테스트와 운영 문서

초기 구현 전 전체 프로젝트 그래프를 만든다. 이후 문서·기능이 추가되면 증분 갱신한다. 기능 변경 전에는 관련 화면, 데이터 필드, 프롬프트, 검증 규칙의 연결을 조회한다.

## 12. 향후 단계

### 2단계: 예약 준비

- 콘텐츠 캘린더
- 예약 희망 시간
- 최종 확인 상태
- 게시 준비 파일 묶음
- Instagram 계정 성과 데이터 읽기

### 3단계: 사용자 승인 후 자동 게시

- Instagram 공식 API 연결
- 게시 전 최종 승인
- 실제 게시 여부 확인
- 중복 게시 방지
- 인증 만료와 실패 복구
- 전체 자동 게시 중지 기능

### 트렌드 추천 확장

- Instagram 계정 도달·저장·공유 등 자체 성과
- 공식 API에서 허용되는 관련 해시태그 데이터
- 별도 허용 데이터원의 지역·검색 트렌드
- 콘텐츠 자료와 실제 가게 정보

AI는 위 신호를 모은 뒤 다음을 함께 제안한다.

- 추천 주제
- 추천 이유와 데이터 출처
- 연결되는 홍어·메뉴 정보
- 대상 고객
- 필요한 사진과 구도
- 피해야 할 과장 또는 억지 연결

실시간 인기 검색어를 제공한다고 확인되지 않은 API에 의존하지 않는다.

## 13. 첫 버전의 완료 기준

- 사용자가 네 단계 안에서 초안을 완성할 수 있다.
- 실제 사진, AI 이미지, 혼합 방식이 모두 동작한다.
